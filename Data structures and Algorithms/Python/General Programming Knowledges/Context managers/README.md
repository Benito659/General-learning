## Context Managers
Context managers is an object that allocates and releases resources precisely when you need them, most commonly utilized via the with statement. They guarantee that setup and cleanup actions are performed automatically - such as closing a file or disconnecting from a database—even if your code throws an error or encounters an exception.

### Try ... Finelly
- we can use a try ... finally block to deal with this issue. 
- In contrast to an except block, which only runs in case the try block throws an exception, The code in the finally block will always be executed, whether the try block threw an exception or not.
```python
    # set up a thing
    connection = open_db_connection()

    try:
        # use a thing
        run_analysis(connection)
    finally:
        # clean up the thing
        connection.close()
```
- One of the downsides is that the 'set up' of the connection and the 'clean up' of the connetion are separated by a **(potentially quite large) block of code**. 
- This makes it quite easy to do the 'wrong' thing and forget to close the connection.
- Python tries to make it hard to do the wrong thing
- To that end, PEP-310 first introduced a bit of syntax to the language that made it impossible to forget to clean up resources, the with statement.
- Using this with statement **(a context manager)**, the code snippet can be simplified to: 
```python
    with open_db_connection() as connection:
        run_analysis(connection)
```


### From Scratch our Own Context Managers
- there are two methods (__enter__ and  __exit__) of a class
- the class will behave as a context managers
- __enter__ is there to set evry things up 
- __exit__ is there to shut down evry thing
- the code that is in the with bloc code will execute between those two methods
- even when there is an error the __exit__ will still exectute
- the as that we have over the context manager declation at **with** bloc code is when we make a return in the __enter__ methods.
```python
    class PrintingContextManager:
        def __enter__(self):
            print('entering the context manager')
            return "i am the returned value"
        
        def __exit__(self, exc_type, exc_value, traceback):
            print('exiting the context manager')

    with PrintingContextManager() as var :
        print('inside the context manager')
        print(var)
        raise ValueError("oh no!")
```


### Context Managers Decorators
- there is another way to create context managers using deocators
- We can rewrite this context manager in a more consise way by using a **generator** and a **decorator**.
```python
    from contextlib import contextmanager

    @contextmanager
    def printing_context_manager():
        print('entering the context manager')
        yield "i am the returned value"
        print('exiting the context manager')


    with printing_context_manager() as var:
        print('inside the context manager')
        print(var)
```
- Everything that occurs before the yield statement can be seen as the code that would run in **__enter__** beforehand and the code that would run after could be seen as the **__exit__** before. In general this functional take is seen as a simpler method of implementing context managers



### Utilities
- utilities for context managers are helper functions, decorators, and classes provided primarily by the built-in contextlib module.
-  they simplify, enhance, and dynamically manage resources inside with statements. 
- **open** help to open the file, read it and do a lot
- when the bloc is over, it stop read the file
- we also have tempfile, that help build temporary file and temporary directory
- useful for unitest
- @contextmanager, ExitStack, closing(), suppress(*exceptions), redirect_stdout() / redirect_stderr(), chdir()
- **yield** keyword pauses a function's execution and returns a value to the caller, turning that function into a generator object. Unlike return, which destroys the function's state and terminates it entirely, yield saves the exact state of the function so it can resume right where it left off when the next value is requested.


### Redirect
- In the context of Python's context managers (specifically the contextlib module), a redirect temporarily changes where system streams like standard output (sys.stdout) or standard error (sys.stderr) send their data.
- Capturing Output: Instead of text being printed to your terminal, it is routed to an in-memory buffer so your script can read and analyze it.
- Suppressing Noise: You can temporarily mute print statements or warnings generated by third-party libraries.
- Logging: You can seamlessly pipe script output directly into a file without modifying the original code.

- exemple : 
```python
    import io
    from contextlib import redirect_stdout

    from sklearn.ensemble import RandomForestRegressor
    from sklearn.datasets import make_regression

    X, y = make_regression(n_features=4, n_informative=2, random_state=0, shuffle=False)

    regr = RandomForestRegressor(
        max_depth=2,
        n_estimators=5,
        random_state=0,
        verbose=100 # <---------- this is what makes sklearn print
    )

    with redirect_stdout(io.StringIO()) as f:
        regr.fit(X, y)
        print(f.get_value())

```
